## 异步 async/await

> CPU 阻塞在不需要 CPU 的时间中

**async 异步函数说明**：告诉运行环境这个函数里面包含一些耗时操作

**await 交出控制权**：用在 `async` 函数内部，让 CPU 执行别的代码

### 异步 `await` 操作完成后，底层是如何通知恢复执行的？

- 挂起，得到 OS 给的号码牌，叫文件描述符 FD
- 运行环境把 FD 登记到内部事件循环中
- 事件循环 while true，调用 epoll 问有哪个 FD 可以读写了？
- 翻登记册把协程返回可执行队列中，轮到它时把拿到的数据塞进去，代码重 await 的下一行继续往下执行

### 什么时候需要 OS 的线程，什么时候用户态线程就够了

你的任务是“需要真正的**算力**”还是“只是在**干等**”。

> 用户态的协程再怎么切换，如果它只绑定在一个 OS 线程上，那它永远只能利用 1 个 CPU 核心。如果你需要做视频渲染、训练大模型、复杂的矩阵运算，你需要真正的算力。这时候必须开启多个 OS 线程（甚至多进程），让操作系统的调度器把它们分配到物理 CPU 的不同核心上同时跑。

**M:N 调度模型**。Go 在底层自动开启了多个 OS 线程（等于你的 CPU 核心数），然后把成千上万个用户态协程（Goroutine）动态、均匀地扔给这几个 OS 线程去执行。

### 进程、线程、协程

- 进程（重）：**分配资源的基本单位**
- 线程：OS 进行 **CPU 调度的基本单位**，**共享线程资源**
- 协程（Go 内置了一个调度器，没有 OS 的线程调度）：**用户态轻量级线程，由编程语言的调度器控制**
